# Phase 1 Data Model: Landing, Authentication & Analytics Dashboard

**Feature**: `001-landing-auth-dashboard`
**Date**: 2026-10-28
**Spec**: [spec.md](./spec.md)
**Research**: [research.md](./research.md)

## Conventions

- **Primary keys**: standard Rails `bigint` `id`.
- **Money**: integer `*_cents` columns (`bigint`), USD, never floats. Formatting only happens in the presentation layer.
- **Dates**: `date` columns for facts (no timestamps), ISO `YYYY-MM-DD` in props. No timezone conversion is applied to reporting dates.
- **Rates**: percentages stored as integer basis points (0–10,000) to avoid floating point; exposed to the client as numbers with one decimal.
- **Tenancy**: every analytics record is scoped to a `workspace_id` (single-workspace demo per the spec assumptions).
- **Timestamps**: `created_at`/`updated_at` on mutable records; fact tables include them for consistency but are only written by seeds.
- **Referential integrity**: foreign keys with `on_delete: :cascade` from workspace-scoped records; users/sessions cascade from users.

## Entity Relationship Overview

```text
Workspace 1 ── * User 1 ── * Session
    │
    ├── * DailyMetric        (one row per workspace per date)
    ├── * SalesRecord        (one row per workspace, date, region)
    ├── * SubscriberSnapshot (one row per workspace per date)
    ├── * ChannelRevenue     (one row per workspace, date, channel)
    ├── * Integration        (ordered display records)
    └── * Message            (read/unread badge source)

Current (ActiveSupport::CurrentAttributes) holds the active Session and User.
```

## Tables

### `workspaces`

The tenant whose analytics are displayed. Exactly one demo workspace is seeded.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `name` | string | null: false, unique | "Marketing" in seeds |
| `plan` | string | null: false, default: "Team" | Sidebar switcher label |
| `currency` | string(3) | null: false, default: "USD" | ISO 4217; only USD used |
| `created_at`, `updated_at` | datetime | null: false | |

Indexes: unique index on `name`.

Validation: `name` presence/uniqueness; `currency` inclusion in `%w[USD]` (keeps formatting deterministic).

### `users`

Generated by the Rails 8 authentication generator, then extended.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `name` | string | null: false | Display name ("Young Alaska") |
| `email_address` | string | null: false, unique, normalized (strip + downcase) | Login identifier |
| `password_digest` | string | null: false | `has_secure_password` (bcrypt) |
| `role` | string | null: false, default: "Business" | Profile subtitle |
| `workspace_id` | bigint | null: false, FK → workspaces | Single workspace per user |
| `created_at`, `updated_at` | datetime | null: false | |

Indexes: unique index on `email_address`; index on `workspace_id`.

Validations: `name` presence (max 80); `email_address` presence, format, uniqueness (case-insensitive), max 254; `password` minimum 8 characters when present; `password_confirmation` matches when supplied; `role` presence (max 40).

Behavior: `normalizes :email_address`; `has_many :sessions, dependent: :destroy`; `belongs_to :workspace`; `has_secure_password`.

### `sessions`

Generated by the Rails 8 authentication generator, extended for inactivity expiry.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `user_id` | bigint | null: false, FK → users, index | |
| `ip_address` | string | nullable | Audit metadata |
| `user_agent` | string | nullable | Audit metadata |
| `last_active_at` | datetime | null: false, index | Expiry source of truth |
| `created_at`, `updated_at` | datetime | null: false | |

Indexes: `user_id`; `last_active_at` (pruning).

State transitions:

```text
create (sign-in/sign-up) → active (last_active_at = now, cookie expires in 30 days)
active --request--> active (last_active_at touched; stale rows destroyed)
active --sign-out--> destroyed (row deleted, cookie cleared)
active --30 days idle--> expired (destroyed on next resume attempt; cookie cleared)
```

Validations: `belongs_to :user`.

### `daily_metrics`

One row per workspace per day; the source for the three KPI cards.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| `workspace_id` | bigint | null: false, FK, index | |
| `recorded_on` | date | null: false | Unique per workspace |
| `page_views` | integer | null: false, default: 0, >= 0 | KPI 1 |
| `sessions_count` | integer | null: false, default: 0, >= 0 | Bounce-rate denominator |
| `bounced_sessions` | integer | null: false, default: 0, 0..sessions_count | Bounce-rate numerator |
| `revenue_cents` | bigint | null: false, default: 0, >= 0 | Net revenue KPI (distinct from gross sales) |

Indexes: unique `(workspace_id, recorded_on)`; index `(workspace_id, recorded_on)` for range scans.

Derived: `bounce_rate_bps = (bounced_sessions * 10_000.0 / sessions_count).round` (0 when no sessions).

### `subscriber_snapshots`

One row per workspace per day; the source for the Total Subscriber card and its seven-day series.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|

Indexes: unique `(workspace_id, recorded_on)`.

Derived: period total `SUM(count)`; previous-period total for the delta; last seven rows in the period ordered by date for the bar series; peak = maximum `count` among them.

## Aggregates and Formulas

| Panel | Source | Formula |
|-------|--------|---------|
| Page Views KPI | `daily_metrics` | `SUM(page_views)` for `period`, delta vs `comparison_period` |
| Total Revenue KPI | `daily_metrics` | `SUM(revenue_cents)`; percentage delta vs comparison |
| Bounce Rate KPI | `daily_metrics` | `SUM(bounced_sessions) / SUM(sessions_count)` scaled to a percentage, compared with the previous period's weighted rate |
| Sales Overview series | `sales_records` | `SUM(amount_cents)` grouped by bucket (calendar month for monthly, ISO week for weekly) and `region`; missing series render as 0 |
| Sales Overview headline | `sales_records` | `SUM(amount_cents)` for the period; growth = difference and percentage vs comparison period |
| Total Subscriber | `subscriber_snapshots` | `SUM(count)` for the period; delta amount and percentage vs comparison; peak = `MAX(count)` in the last seven days |
| Subscriber series | `subscriber_snapshots` | Last seven dated rows within the period, labeled by weekday (Sun–Sat) |
| Sales Distribution | `channel_revenues` | `SUM(amount_cents)` grouped by `channel` for the period; percentages computed client-side from amounts |
| Integrations | `integrations` | Ordered rows, search filter, limit 3 or all |
| Sidebar badge | `messages` | `COUNT(*) WHERE read_at IS NULL` |

**Period rules**: inclusive `start_date..end_date`; `comparison_period` length equals the selected period length and ends the day before `start_date`; range length capped at 366 days; bucket boundaries use `Date` values (no time component, no timezone drift).

**Delta formatting**: percentages rounded to one decimal. A zero previous value yields "—" (no comparison) rather than infinite growth. Direction is `up` when delta > 0, `down` when < 0, `flat` when 0.

## Seed Dataset (deterministic)

Seeds are idempotent (`find_or_create_by!`/upsert keyed by natural keys) and safe to re-run:

1. **Workspace** "Marketing", plan "Team", currency USD.
2. **Users**: demo account `Young Alaska <demo@nexus.io>` with role "Business" and a documented password; belongs to the demo workspace.
3. **Messages**: 8 unread rows (badge = 8).
4. **Daily metrics**: every day from `2023-09-01` to `2023-12-31`, tuned so the default period (2023-10-18..2023-11-18) yields page views 12,450, net revenue 36,395 cents, and a weighted bounce rate of 86.5%, while the comparison period yields the ratios behind +15.8%, −34.0%, and +24.2%.
5. **Sales records**: daily rows per region from `2023-09-01` to `2023-12-31`, tuned so October totals 298,820 cents, November 176,509 cents, December 400,565 cents, and the default period total is 475,329 cents, with the comparison period behind the displayed growth.
6. **Subscriber snapshots**: daily rows with a period total of 24,473, a comparison total 749 lower, and a 3,874 peak within the last seven seeded days (Sunday–Saturday labels).
7. **Channel revenues**: daily rows yielding Website 37,482 cents, Mobile App 24,160 cents, Other 21,342 cents for the default period.
8. **Integrations**: the three reference rows (Stripe/Finance/40%/$650.00, Zapier/CRM/80%/$720.50, Shopify/Marketplace/20%/$432.25) plus three additional rows used by "See All".
9. **Sessions**: none seeded; users sign in normally.

Seed constants live in one module (for example `DemoData`) consumed by `db/seeds.rb`, tests, and the sign-in demo hint, so credentials and reference dates are not duplicated.

## Query Objects

| Object | Responsibility |
|--------|----------------|
| `Dashboard::Period` | Parse/validate `start_date`, `end_date`, `granularity`; expose `range`, `comparison_range`, `bucket` (`:month`/`:week`), labels |
| `Dashboard::Filters` | Validate `regions[]`/`channels[]` against allowed values; expose labels and active-filter state |
| `Dashboard::Metrics` | KPI aggregates + deltas + display-ready numbers |
| `Dashboard::SalesOverview` | Bucketed regional series, month totals, headline total, growth |
| `Dashboard::Subscribers` | Period total, delta, seven-day series, peak day |
| `Dashboard::Distribution` | Channel totals and shares |
| `Dashboard::Integrations` | Ordered, filtered rows plus result count and "See All" state |
| `Dashboard::Navigation` | Sidebar groups, disabled entries, unread badge |
| `Dashboard::Payload` | Assemble the full page props from the objects above (single entry point for index/export) |

No model callbacks compute aggregates; all derived data is read-only and computed at request time.

## Data Integrity Rules

- All fact-table writes are workspace-scoped and validated with DB check constraints (`>= 0`, `rate BETWEEN 0 AND 100`, `bounced_sessions <= sessions_count`).
- Deleting a workspace cascades to its users, sessions, facts, integrations, and messages.
- Deleting a user cascades to sessions; analytics facts remain workspace-owned.
- Daily uniqueness prevents duplicate seeding and double-counting.
- Seeds must pass `RAILS_ENV=test bin/rails db:seed:replant` (existing CI step).
